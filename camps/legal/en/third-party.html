1. Overview

The System uses third-party services and software, each with its own terms and privacy policy. By using the System you acknowledge that some data is sent to the providers named here. Providers’ terms can change; please check the latest version at the links given. If this page conflicts with a provider’s original documents, the originals prevail.

All fonts and scripts are loaded from our own server. There are no calls to Google Fonts or external CDNs, so your IP address is not sent to those companies.

2. Fonts

Inter and Noto Sans Thai

What it does here: Show Latin text (Inter) and Thai text (Noto Sans Thai) on the website. The font files sit on our own server (/assets/fonts).

Data involved: None; the browser requests the files from our server only.

Terms and policies: Both are variable fonts released under the SIL Open Font License 1.1, which allows free use and distribution, including commercial use. The files come from the projects’ Fontsource packages; the licences are kept next to the font files. openfontlicense.org

Sarabun (font for generated PDFs)

What it does here: Embedded in PDF files the System creates in the browser (for example sign-in sheets) so Thai displays correctly.

Data involved: No user data leaves the System.

Terms and policies: Sarabun was designed by Cadson Demak and is released under the SIL Open Font License 1.1. The file used may be a version prepared for PDF under that licence. openfontlicense.org

3. Sign-in

Auth0 (Okta)

What it does here: Handles sign-in and sessions through the domain auth.litalkeducation.com.

Data involved: Email, name, profile picture, email-verified status, sign-in time and session tokens. Auth0 processes these as the Organiser’s service provider.

Terms and policies: Auth0 is an Okta product. Auth0 legal documents · Okta privacy policy

Google Account (sign-in channel)

What it does here: Uses your university Google account to verify identity. This is the only Google service the System uses.

Data involved: Your email address, name and profile picture (basic information only). When you sign in, Google knows you are using this System through Auth0.

Terms and policies: Use of Google accounts is under Google’s terms and policies. Google Terms · Google Privacy Policy

4. Infrastructure and hosting

Cloudflare (Pages, Workers, D1, R2)

What it does here: Serves the website, API, database (D1) and file storage such as shirt pictures and attachments (R2), plus the delivery network and attack protection.

Data involved: All data you enter is stored in Cloudflare’s services. Technical access logs (for example IP) are processed by Cloudflare, possibly outside Thailand.

Terms and policies: Cloudflare’s terms: Website Terms · Self-Serve Subscription Agreement · Privacy Policy

GitHub (and GitHub Actions)

What it does here: Stores the System’s source code and deploys it to the web automatically.

Data involved: No personal data of System users is stored in GitHub (only code and non-secret settings).

Terms and policies: GitHub’s terms: Terms of Service · Privacy Statement

5. AI-image check

Sightengine (AI-generated image detection)

What it does here: Helps estimate whether a submitted shirt design is likely AI-generated. It is only an aid; the Organiser decides, and if the service does not respond students are never blocked (see Privacy Policy section 5).

Data involved: The shirt picture you upload is sent to Sightengine for analysis and a probability score comes back. We store the score and summary in our own database. No name or other personal data is sent with the picture.

Terms and policies: See the provider’s latest terms and privacy policy on its website: sightengine.com

7. Browser features and notifications

  • Camera: used to scan QR codes; images are read on your device and not uploaded.
  • Location: used to check you are inside the registration area when the Organiser enables it. Only the distance and accuracy are stored, never raw coordinates.
  • Browser notifications (Web Push) in the budget system: if you enable them, your subscription is sent through your browser maker’s push service (for example Google, Apple, Mozilla), which has its own policy. You can turn them off in browser settings.
